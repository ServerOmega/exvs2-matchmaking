Connecting your game to a matchmaking server
============================================

Every player needs 3 things:
  A. the game talking to a card server that has online matching turned on,
  B. the game set to ONLINE matching (battleMode 0),
  C. the network open for the battle itself (game to game, UDP).

The host gives you ONE address: the matchmaking server's IP (public IP, or VPN IP if your group uses a VPN).
Example used below: 203.0.113.10


A. Point the game at a card server  -  pick ONE way
----------------------------------------------------
Way 1: Use the host's server as your card server  (simplest; your cards live on the host's server)
  In the game's POC config.ini (in your game folder), section [config]:
      Server = 203.0.113.10
  Only the IP. No "http://", no port. The game talks to the card server on port 28080, so this only
  works when the host's card server listens on 28080 (typically a LAN or VPN host, not a public VPS).
  A public / VPS matchmaker listens on 28090 and does not serve cards to the internet — use Way 2.
  Your old cards are NOT on the host's server: you start fresh there (or the host imports your database).
  Since v0.4.0-pre a host on a PUBLIC IP serves only matchmaking to the internet by default
  (AccessMode PublicMatchmaker). Way 1 then works only over a VPN / LAN, or if the host chose
  "internet players load cards from this server" in 2-Configure. Otherwise use Way 2.

Way 2: Keep your own card server on your PC, match on the host's server  (cards stay with you)
  Use this if you play with SnowLauncher: SnowLauncher ignores its Server= setting and the game always
  talks to 127.0.0.1:28080 (this PC).
    1. On YOUR PC: run 1-Build-Server.bat, then 2-Configure.bat and choose "2 = PLAY",
       and type the host's address (203.0.113.10). Then 3-Start-Server.bat.
       This writes, in server\Configurations\server.json -> CardServerConfig -> OnlineMatching:
           "Enabled": true,
           "MatchUrl": "http://203.0.113.10:28090/match",     <- the host's matchmaker (port 28090)
           "StunHost": "203.0.113.10",                         <- the host's STUN
           "BuiltinStun": false
       The matchmaker is on 28090; your own card server (and its web page at
       http://127.0.0.1:28080/) stays on 28080. 2-Configure "2 = PLAY" assumes 28090.
       If the host changed the matchmaker port, change only the port in MatchUrl.
    2. Your game keeps  Server = 127.0.0.1  (POC config.ini default) - SnowLauncher does that by itself.
    3. Close any OTHER card server on your PC first (only one program can use port 28080),
       e.g. the official Server.exe. Your cards: copy ServerInfinite.db into server\ (step 1 can do it for you).
       SnowLauncher always starts the stock card server from the game's server folder. Start the patched
       server FIRST (3-Start-Server.bat, wait until it is listening), then open SnowLauncher: the stock
       server cannot get port 28080 and the game uses the patched one (close the stock server's window if
       it shows one). Or rename the game's server folder (e.g. server.original) and put the patched
       server build in a new server folder, so SnowLauncher starts the patched one itself.
    4. In SnowLauncher.ini set PCB_IpAddress and LM_IpAddress to THIS PC's LAN IP (the address other machines
       on your home network use to reach it), not 127.0.0.1.
    5. Close SnowLauncher before you edit its ini: it keeps the file in memory, so a change made while it is
       open is ignored or overwritten. Then reopen it.
  Results and cards are saved on YOUR card server; only the matching happens on the host's server.
  (Tested 2026-11-13 on one PC with two card servers.)
  For online tag across card servers you also need the host's TagSecret: 2-Configure "2 = PLAY" asks for it,
  or paste it as "TagSecret" under CardServerConfig -> OnlineTag in server\Configurations\server.json and
  restart the card server. The host finds it as described in Public-Server.txt (Security). Share it privately.

  Keep a backup of your launcher / card settings: SnowLauncher once wiped the AccessCode in its ini during testing.


B. Switch the game to ONLINE matching  (battleMode 0)
------------------------------------------------------
  The game only uses the online matchmaker when the ACTIVE setting entry in  testmode_pcb.json  has
      battleMode: 0
  Any other value = in-store / LM matching only.
  Where the file is: in the "29" folder inside your game folder (the folder that has the game exe), e.g.
      <your game folder>\29\testmode_pcb.json
  Every cabinet copy (each install folder) has its own 29\testmode_pcb.json; change each one.
    - Close the game first and BACK UP testmode_pcb.json (copy it to e.g. testmode_pcb.json.bak).
    - Open it in a text editor (Notepad works) and search for  battleMode . Each entry looks like:
          ".TestModeParam.gameServerPcb.settingFile.[0].group.[0].battleMode": {
            "value": 1,
            "type": 1
      Change only "value" to 0. Leave "type" alone (it says the field is a number; changing it breaks the file).
    - The game picks one "group" entry by time slot, so set "value": 0 on EVERY group.[N].battleMode under
      the active settingFile (settingFile.[0] unless you changed it). Keep the commas/braces intact and save.
    - Never use "EXIT & SAVE" in the in-game test menu (it rewrites the file), and don't edit the file while the
      game runs.
  How to check: start the game, pick an online mode; the server log shows "MMS IssueNodeId" and
  "NET entry ..." for your cabinet. If you only see "NET register-pcb", battleMode isn't 0.
  The SERVER needs no LM. On your side keep your usual setup: if your game normally runs with an LM, keep the
  LM running (in our tests each cabinet had its own LM running; playing online with the LM closed is untested).
  LM discovery is a LAN broadcast (UDP 49000). Two LMs on the SAME home network can claim each other's cabinets.
  If two people in one house each run their own LM (for example to simulate internet players), run only one LM
  on that LAN, or isolate them: a different adapter / IP / subnet for each LM+cabinet pair, or a firewall rule
  that blocks UDP 49000 between the two PCs. Never forward UDP 49000.



B2. Give your game its OWN serial  (everyone must be different)
---------------------------------------------------------------
  The matchmaker tells cabinets apart by their serial + internet address. Two players with the SAME serial
  (for example both kept the default, or copied a game folder from a friend) kick each other out of the queue
  and never match. In the server log this shows as:  drop nodes=[...] reason=same cabinet entered again
    - Close the game and SnowLauncher first.
    - Pick a random 4-character serial made of letters and digits, e.g.  k7Qm  (don't copy this one, make
      up your own). Every cabinet / game folder needs a different one, even on the same PC.
    - Put the SAME value in both places:
          SnowLauncher.ini   [Game_Config]   Serial=k7Qm
          config.ini                         serial =k7Qm   (keep the line format your file already uses)
    - Restart SnowLauncher so it reads the new value.

B3. Give every cabinet its OWN card  (do not copy another folder's card)
------------------------------------------------------------------------
  A serial is the cabinet; a card is the player. If you copy another game folder's card.ini (or the card
  fields in its SnowLauncher.ini), both cabinets are the SAME player and teams / names / results get mixed up.
    - Access code: 20 decimal digits. Chip id: 32 uppercase hex characters (0-9A-F).
    - Put the SAME pair in the game folder's card.ini (accessCode / chipId, or AccessCode / ChipId if that
      is how your file is already written) and in SnowLauncher.ini (typically [Game_Config], AccessCode=
      and ChipId=).
    - Close the game and SnowLauncher first, then paste, then reopen.
    - Generate a fresh pair in PowerShell (this only prints values; make your own, do not reuse an example):

          $access = -join (1..20 | ForEach-Object { Get-Random -Maximum 10 })
          $chip   = -join ((1..32) | ForEach-Object { '{0:X}' -f (Get-Random -Maximum 16) })
          "AccessCode=$access"
          "ChipId=$chip"

      The first card insert on a new pair registers a new player on that card server.

C. Network for the battle itself
--------------------------------
  The matchmaking server only introduces players. The battle runs DIRECTLY between the players' games (P2P, UDP).
    - Firewall: allow the game exe (and your launcher) in Windows Firewall / TinyWall. With TinyWall, every
      copy of the game folder is a different exe path and needs its own entry.
    - Home router: the game's battle port is UDP 48000 (plus a small per-terminal offset). It has no UPnP.
      If matches form but the battle never starts, forward UDP 48000 and the next few ports (e.g. 48000-48010)
      to your PC, or everyone joins the same VPN (Tailscale / ZeroTier / Radmin / N2N).
    - NEVER forward UDP 49000 - that's the LM's local broadcast, it must stay in your home.
    - With a VPN: set the POC config.ini  IpAddress = <your own VPN IP>  (or InterfaceName = <VPN adapter
      name>) so the game uses the VPN adapter (only one of the two may be active - put # before the other). Everyone in the group must be on the same VPN network,
      and the host's VPN IP is the server address.


Then play
---------
  1. Start the game, insert your card, pick an online mode. EVERYONE must pick the SAME mode to meet
     (each mode has its own queue).
  2. 4 players searching = a 2v2 right away. With 2-3 players the search waits until a 4th human
     joins, or until each cabinet's own matching timeout (~150 s). Fes 1on1 only needs 2 players.
  3. Cancelling the search in the game works.

Online tag (play as a team with a chosen partner) — confirmed in the real game 2026-11-15, including
partners on different card servers that share one matchmaker:

  Same card server:
  1. Your partner opens the card website  http://<card server IP>:28080/  , logs in with their card,
     opens Customize -> Teams and sends you "Your User ID" and "Your Invitation Code" (privately; it works once).
  2. You open your own Customize -> Teams, enter them under Add Team, press ADD.

  Different card servers (each server has its own ServerId; MatchUrl / StunHost point at the same
  matchmaker, e.g. http://<VPS_IP>:28090/match — the matchmaker is on 28090; your own card
  server (and its web page at http://<card server IP>:28080/) stays on 28080. Every card server needs the matchmaker's online-tag
  shared secret - 2-Configure "2 = PLAY" asks for it, or set TagSecret under OnlineTag in server.json;
  the matchmaker's host gives it to you privately, never in a public chat):
  1. Each of you opens YOUR own card website -> Customize -> Teams.
  2. One partner taps "Create a code" and sends the 8-character code to the other.
  3. The other types it under "Partner's code" and taps Join. The creator reopens the Teams tab.
  4. Team name / BGM / effect saved on one side show up on the other after a refresh or card reinsert.

  In the game (both setups):
  1. Both re-insert your cards. On TEAM SELECT pick オンラインタッグ (Online Tag) — not Mix Match,
     Class, Fes, or 店内チーム — choose the shared team, and search at about the same time
     (each waits up to 90 s for the other).
  2. After the duo forms, a 2v2 still needs two more human players. Two online-tag duos (even one
     cross-server and one same-server) form one 2v2 together - tested 2026-11-15 with 4 cabinets.
  3. If one of you searches alone, the matchmaker log says "TAG-WAIT ... waiting for partner N:
     partner not searching" - the partner's cabinet hasn't started an Online Tag search.
  4. Partner display names on the matchmaker are stored when the team is created or joined. A fix that
     syncs renames on card insert and lets either member delete a team is not yet in a published package.
     Until every card server and the matchmaker run that update, a renamed partner can stay stale and a
     deleted team can reappear after a card insert.

Friend requests (results-screen OPTION, hold Start, pick フレンド申請) are not supported yet (planned).
  They are partner-only and both players must be on cards. Keep PostMatchStubs true in the card server's
  server.json (CardServerConfig) so the game gets an empty reply; with it false the game shows an
  "Unhandled case" error. A friend request does not create an online-tag team today.
