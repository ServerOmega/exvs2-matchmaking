Troubleshooting
===============

Building (1-Build-Server.bat / linux/build-server.sh)
------------------------------------------------------
  "running scripts is disabled"     use the .bat file (it runs PowerShell with -ExecutionPolicy Bypass).
  Download errors                   check your internet; antivirus/proxy may block github.com or dot.net. Run it again.
  "The patch does not apply"        the downloaded source changed - please report it on the project page.
  Build errors about paths          move the folder to a short, English-only path like C:\exvs2-server.
  "The server is running"           close the 3-Start-Server window (or stop the service) before rebuilding.
  Windows SmartScreen on the .bat   "More info" -> "Run anyway". The scripts are plain text; you can read them first.

Starting (3-Start-Server.bat / linux/start-server.sh)
------------------------------------------------------
  Window closes / "address already in use"   another card server already uses port 28080 (e.g. the official
                                     Server.exe). Close it - only one program can use the port.
  "STUN built-in server could not bind UDP 3478"   another program (another copy of this server, coturn) uses it.
  A notice window for 5 seconds      normal (the original card server's anti-scam notice). Windows only.
  Linux: "Couldn't find a valid ICU package"   start-server.sh handles this; or install libicu.
  Card website has no pictures       the pictures aren't in the source code. See Import-Pictures.txt:
                                     download Server-Infinite-v1.2.0.zip from the official v1.2.0 release
                                     (https://github.com/Chiang-17/EXVS2-IB-Server/releases/tag/v1.2.0)
                                     and run Import-Images.bat (or ./linux/import-images.sh), or re-run
                                     step 1 and give it the official folder.

Players can't match - read the server log (window or Logs\log-<date>.txt)
---------------------------------------------------------------------------
  No "NET register-pcb" line for the player
      -> their game isn't talking to this card server: wrong Server= address, port 28080 blocked/not forwarded,
         firewall, or (SnowLauncher) they need their own local card server ("2 = PLAY").
  "NET register-pcb" but no "MMS IssueNodeId" / "NET entry"
      -> battleMode isn't 0 in the active entry of <game folder>\29\testmode_pcb.json, or "Enabled" is false on the card server
         that player uses.
  "drop nodes=[...] reason=same cabinet entered again" (repeating every second or two)
      -> two cabinets share the same serial (and internet address): give every cabinet its own random
         serial in SnowLauncher.ini (Serial=) and config.ini (serial =). See Connect-Your-Game.txt, B2.
  "NET-WARN register-pcb ... loopback"
      -> a remote player was given 127.0.0.1: set StunHost to your public/VPN IP (2-Configure.bat).
  "NET entry ... class=stun-missing" / stuck on searching
      -> STUN unreachable: UDP 3478-3479 not opened/forwarded, or StunHost is not the address players reach.
  "entry ..." lines but never "MATCH"
      -> players picked different modes (each mode is its own queue), only one player searching, or players
         on different networks (VPN vs internet) - they are never matched together.
  "MATCH room=..." but the battle never starts
      -> the game-to-game UDP is blocked: allow the game exe in the firewall / TinyWall, forward UDP 48000+
         or use a VPN. Strict / CGNAT internet on BOTH sides can't connect directly (there is no relay).
  "drop nodes=[..] reason=..."       a player left the search (cancel, timeout, stopped responding).

  More log lines: https://github.com/ServerOmega/exvs2-matchmaking/blob/main/analysis/networking-issues.md

Online tag
----------
  No team to pick in the game  -> make the team on the card website first (Customize -> Teams), then re-insert
                                  the card. "TagStatus" in the "OnlineTag" section of server.json must be 1
                                  (the default since v0.3.0-pre; restart the server after changing it).
  Both search but never pair   -> both partners must pick Online Tag (not Team / Mix) and search within ~90 s.
                                  Matchmaker log "TAG-WAIT ... waiting for partner N: partner not searching"
                                  = the partner never started an Online Tag search; "... is in the queue as
                                  node=... but cannot pair" = the partner searched another mode.
  "Create a code" / "Join" fails, card server log "The matchmaker refused this card server: OnlineTag.TagSecret
   in server.json is missing or does not match the matchmaker's."
                               -> the card server's TagSecret is missing or differs from the matchmaker's.
                                  Ask the host for it privately, paste it (2-Configure "2 = PLAY", or
                                  CardServerConfig -> OnlineTag -> TagSecret in server.json), restart the
                                  card server. Hosts: the value is in the matchmaker's server.json (Windows:
                                  server\Configurations\server.json; Linux package: server-linux/Configurations/
                                  server.json; VPS: /opt/exvs2-mm/Configurations/server.json). Read commands
                                  and how to rotate: Public-Server.txt (Security) and the setup guide A8.
  Partner name stays old, or a deleted team comes back after a card insert
                               -> mixed old/new servers. This pre-release syncs renames and deletes;
                                  upgrade every card server and the matchmaker.
  フレンド申請 (friend request) on the results screen errors, or the card server logs "Unhandled case"
                               -> card server older than this release. Upgrade it, or keep
                                  PostMatchStubs true so the game gets an empty reply instead of an error.
  Searching a long time even though four people want to play
                               -> the server matches instantly once four compatible humans are in the
                                  same queue. Everyone pick the same mode (Mix, Class solo and Class team
                                  never mix). Wait until all four are on the search screen. After a pair
                                  cancel a cab can be held up to 3 minutes until a title-screen restart.
                                  Three humans wait for a fourth (no CPU teammate). See Known issues.
  Live Monitor 21-01 on every cabinet at once
                               -> the matchmaker (VPS) restarted, or the LM was closed. Restart the
                                  cabinets after the matchmaker / LM is back.
  Pair sees a partner-lost / CPU prompt, then a black screen
                               -> the game cancelled a first pair search at about 30 seconds. A pair
                                  that requeues after a CPU loss is sent a CPU room on the first poll
                                  (~3 s, ContinuePairAfterCpuSeconds; confirmed 16 Nov 2026). If a
                                  prompt still appears, release the partner on the other cab, or wait
                                  about 2 minutes, then come back through the title screen.
  Two LMs on one home network steal each other's cabinets
                               -> LM discovery is a LAN broadcast (UDP 49000). Run only one LM on that LAN,
                                  or isolate the two PCs (different adapter/IP/subnet, or a firewall rule
                                  blocking UDP 49000 between them). Never forward UDP 49000.
  Two cabinets act as the same player (teams / names mixed up)
                               -> they are using the same card. Each cabinet needs its own 20-digit access
                                  code and 32-hex chip id in card.ini and SnowLauncher.ini. Do not copy
                                  another folder's card. See Connect-Your-Game.txt, B3.

Security refusals (v0.4.0-pre) - log line "SEC-REFUSE <status> ..."
-------------------------------------------------------------------
  403  the source is not allowed by "AccessMode": the card website from the internet on a PublicMatchmaker
       server (correct), a VPN range missing from "ExtraAllowedCidrs", or a player using a public host as
       their card server (Way 1) - use Way 2, a VPN, or (not recommended) AccessMode "Open".
  401  /tag without the right TagSecret (see Online tag above).
  429  too many requests from one IP (/match 1200/min, /tag 240/min) - a script or a broken client.

Settings reference (server\Configurations\server.json -> CardServerConfig)
--------------------------------------------------------------------------
  OnlineMatching:  Enabled, MatchUrl, StunHost, StunPort, BuiltinStun, FillAfterSeconds (3),
                   FillTimerMode (Rolling), MaxFillWaitSeconds (3),
                   InStoreFillAfterSeconds (3), InStoreMaxFillWaitSeconds (3),
                   OneOnOneWorlds ("20"), NoCpuPartner (true), ContinuePairMode (VsCpu),
                   ContinuePairSeconds (18), ContinuePairAfterCpuSeconds (2),
                   PairCancelQuarantineSeconds (180),
                   AllowPartialRooms, CpuStandInSeats (keep false),
                   LogResultGap, LogPostMatchTraffic, PollingIntervalSeconds, StaleAfterSeconds,
                   NetworkRealms, VerboseLog ...
  OnlineTag:       SendTagTeams, TagStatus, MaxTeams, OneTimeInviteCode, TagSecret, ServerId
  Full list: https://github.com/ServerOmega/exvs2-matchmaking/blob/main/server-sketch/ib-server/README.md#configure
  Restart the server after editing. Keep a copy of the file before editing by hand.

KNOWN ISSUES (this is an early test build)
------------------------------------------
  1. Results screen hangs after a versus match when BOTH cabinets run on ONE PC. It also happens in local
     LM mode without this server. A 4-human 2v2 on 2026-11-14 cleared results; hung rooms were 2 humans +
     2 game-added CPUs. Not seen in solo matches vs CPU. (Under investigation.)
     Test options and tools that help narrow it down: see Results-Hang-Testing.txt.
     2v2 matches only form with 4 human players (NoCpuPartner, default on). Fes 1on1 needs 2.
  2. Two cabinets on one Windows PC (2026-11-13), plus a Fes 1on1 and a cross-server online-tag pair
     through a remote matchmaker (2026-11-15). The same day, a second person's from-scratch card-server
     build paired in Online Tag and completed a 4-human Mix Match through the VPS matchmaker (two PCs,
     same house). A two-location NAT test (different homes / VPN) still needs more testers.
  3. Online tag was confirmed in the real game on 2026-11-15, including partners on different card
     servers that share one matchmaker (Create a code / Join on the Teams tab, then pick
     オンラインタッグ on TEAM SELECT). After the duo forms, a 2v2 still needs two more humans.
     Partner recruit (random partner) is less tested. Partner display names are stored at create/join;
     a rename/delete sync is not in a published package yet (stale names or a deleted team can reappear).
  4. The matchmaker keeps the waiting list in memory: restarting the server drops players who are searching.
  5. No relay: two players who both have strict/CGNAT internet may never connect - use a VPN.
  6. Ranked (class match) results are trusted from the game; ranked pairing is by class and level only.
  7. The Linux build was tested on a Linux PC with fake cabinets (no real game against it yet).
  8. Switching the game to online (battleMode 0) is a manual edit of <game folder>\29\testmode_pcb.json
     (see Connect-Your-Game.txt, step B).
  9. Friend requests and online-tag rename/delete sync are in this release; every card server
     and the matchmaker need this build. An older card server should keep PostMatchStubs true.
  10. A pair that loses to CPUs and searches again is sent a CPU room on the first poll (~3 s,
     ContinuePairAfterCpuSeconds=2). Confirmed on cabinets 16 November 2026, 2:06 AM PT (no
     prompt). The pair-cancel guard still stops a dirty re-entry from joining a new room.
  11. Class Match solo and team are separate queues. For a pair plus solos, use Mix Match.
  12. Long waits: the server matches instantly once four compatible humans are in the same queue.
     Mixed modes, staggered search, the game's 150 s timeout, the pair-cancel hold, and waiting
     for a 4th human (NoCpuPartner) are the usual causes. A "3 humans + 1 CPU after a delay"
     option is not implemented.
  13. Live Monitor 21-01: VPS/matchmaker restart, the LM closing, or (before this build) a
     half-reset cab joining a room. Start card servers first, then the LM and cabinets.
  Known issues (full page):
     https://github.com/ServerOmega/exvs2-matchmaking/blob/release/v0.5.0/docs/KNOWN_ISSUES.md

Reporting a problem: https://github.com/ServerOmega/exvs2-matchmaking/issues - include the server log lines
around the problem. Remove access codes / card numbers / BootToken before posting anything.
